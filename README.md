**SillyTavern 1.18+ / Tauritavern 第三方扩展 · 文生图人物一致性方案**

## v1.30.2 提示词分层校正

- H3 overlay 只负责该模型的英文画面表达、空间与接触、肤质、光照和构图，不再重复定义人物档案、造型库存档或立绘协议。
- 人物建档、固定锚点、种子、aura、事实、景别裁剪和立绘规则归 `prompts/roster/system.txt`；造型结构与回传规则归 `prompts/wardrobe-expand.txt`，维度词表归 `prompts/wardrobe-vocab.txt`。
- 本轮档案、造型与占位符实例由 user 消息提供；所选模型 overlay 在共享规则和词表之后加入。另行扫描角色卡使用 `prompts/static-profile/system.txt`，不混入每张图的画师请求。
- 修正共享规则残留的 aura/肤质归属、强制标签和权重写法、立绘表情及覆盖旧立绘的矛盾说明；增加六种模型与两种 system 发送方式的组装验证。

## v1.30.1 H3 提示词完善

- 补全人物首次建档、英文锚点冻结与跨图逐字取用，分清种子、aura、肤质、事实与本轮动态，加入同一人物换景别和换装的对照示例。
- 补全造型 key / detail、景别裁剪、局部入镜、身体条件和立绘基准规则；同步校正 H3 请求中的旧 aura 与标签区说明。
- 画师指令直接描述当前输入与要执行的动作，不依赖外部文档或开发对话。

## v1.30.0 MiniMax-H3-Image

- 模型类型与角色扫描模式新增 **MiniMax-H3-Image**。沿用 Krea 2 的英文自然语言接入方式，使用独立提示词规则、英文档案与缓存；已有 Krea 2 风格选择不会被当作 H3 风格自动拼接。
- 依据 [官方扩写指导](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE/blob/main/prompt/t2i/task_prompt.txt) 和 [官方文生图写作指南](https://github.com/MiniMax-AI/MiniMax-H3-Image/blob/main/skills/h3-image-prompt-writing/references/t2i-en.txt)，描述一幅完整画面，优先主体、单一瞬间、朝向、接触、支撑与空间层次。图像提示词保持纯文本，不采用官方 PE 的 JSON 外壳或画布选择。
- 默认构图接近方形，**宽略小于高**；明确取景优先。插件不改工作流中的宽高或其他参数，也不输出比例建议。需要画出的文字用双引号保留，中文招牌不会被英文清洗删掉。
- 皮肤与解剖规则是减少风险的提示词策略，不能保证消除模型缺陷。照片不反复追加真实皮肤、毛孔、微瑕疵、锐化词；动漫不追加摄影肤质。手部只承担明确、相容的任务，接触轮廓与支撑点保持连贯，不强迫遮挡中的手指全部出现。

### 研究依据与使用边界

[官方模型说明](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image) 明确原生模型不使用 CFG，接口不支持负面提示词。本插件因此使用正向画面描述，不恢复负向词注入。

社区存在相反的肤质体验：[Comfy-Org 讨论 #2](https://huggingface.co/Comfy-Org/MiniMax-H3-Image/discussions/2) 中，一位实测者反馈反复要求真实皮肤会过度强化表面效果；[SillyTavern 用户实测](https://www.reddit.com/r/SillyTavernAI/comments/1xv6gm8/generating_good_images_out_of_sillytavern_with/) 更强调可见互动、接触和明确视点。因此本模式采用克制肤质与关系描述，这是基于官方规则和个别社区经验作出的实现取舍，并非经过统计验证的修复。

[高分辨率测试讨论](https://www.reddit.com/r/StableDiffusion/comments/1xw9oja/the_minimax_h3_image_is_a_beast_at_ultrahigh/) 仍有手指、指甲和肢体失败反馈。输出分辨率、权重量化、VAE、LoRA 及工作流内二次扩写也可能影响结果；仅靠加“完美手部”或皮肤词无法保证解决。若工作流本身还启用提示词扩写，可固定其余条件对比开关效果，插件不会自动解析或关闭这些节点。

使用时选择本模式并导入对应 H3-Image 工作流；若当前人物档案锁定了其他模型，请在档案扫描中选择 H3-Image 重新扫描。切换模式会为当前回复建立 H3 专用结果；同一 H3 回复后续只改一个占位符仍只重做该处。现有艺术家风格输入可选，留空可避免额外风格干扰。

## v1.29.1 修复与新增

- 编辑一处占位符，只分析和生成该处。未改动的占位符保留各自的提示词、图片和图位身份；插入、删除或只改正文也会逐项复用。同文占位符仍是独立图位，swipe 分支保持隔离，兼容 v1.29.0 缓存。
- 完整悬浮窗新增「⏹ 取消全部」：取消分析、等待生图和当前客户端请求（含立绘），自动扫描不会立即重新排入已取消任务。点击图位继续分析，或点击「排图」/单张生成按钮继续生图。
- 已发送给 ComfyUI 的计算可能在服务端继续；插件中止等待并忽略迟到结果，不调用会影响其他客户端的全局中断接口。

## v1.29.0 重构

- 占位符统一解析：同段多图、相同场景、多行、全角符号、跨 HTML 节点均逐个保留位置。
- 生成期间不处理；以原始消息全文 + 聊天 + 楼层 + swipe 分支识别任务和缓存。编辑、续写、重生成后重新识别；旧请求取消且旧结果不得写回。
- 每个占位符独立请求画师模型，结果逐张显示，失败项单独重试，避免多图漏项后串位。代价是 N 个占位符通常需要 N 次辅助模型请求。
- 前端卡绑定来源窗口，支持 `generate` / `generateRaw`，仅消费完成响应；同源 iframe 支持原位渲染。不可访问的跨域 iframe 无法注入。
- 完整删除状态 key 增减协议、状态库、界面及提示词。可见状态直接写在本张图的要点中；旧角色卡/世界书中手工粘贴的指令请更新。
- 悬浮窗随窗口、缩放、旋转、可视视口变化自动回到屏内；未悬停 3 秒收为 logo，悬停或触摸后展开，双击标题恢复默认位置。
- ComfyUI 导入/保存不校验 JSON、不分析节点。发送时只替换 `%prompt%`，保留工作流排版、未知节点、负向词、固定种子、连线及 64 位整数。
- 唯一例外：采样器变体的 `seed` / `noise_seed`（以及模块化采样 `RandomNoise.noise_seed`）为数值 0 时，在发送副本中替换为随机正整数。保存的工作流不变；非零值和连线保留。

开发验证：`npm ci && npm run check && npm test`。应用内核验与预期返回见 [TESTING.md](TESTING.md)。

旧版只存消息前缀，不能可靠区分改写与分支；旧缓存保留，但不再模糊复用到新图位。新版本成功分析后会建立精确缓存。

先把角色长相存进「人物档案」，之后每次出图都按档案引用——**角色不换脸**，衣着、发型、表情、场景跟着剧情走。

## 人物档案机制（一图流）

1. **扫描**：读角色卡 → 脸部（脸型/眉眼/鼻唇/肤色）+ 身形（体型/发型…）→ 写入 `base`（权威，不再变）
2. **每轮**：酒馆 AI 在正文/占位符写的**可变维度**（衣着/发型/表情/光线/氛围）→ 记入 `live`，覆盖只对这一轮生效
3. ***更新***：酒馆 AI 更新外貌时回执 → 插件并入档案
4. **新人物**：正文/占位符报一次外貌即自动建档（NPC、世界观路人同样处理）

核心规则：**档案管「长相」，酒馆 AI 管「穿戴」**。人物段只写名字（同名不同人行带标签），格式必须严格。

## 常见问题

- **人物不一致？** 确认扫描过角色卡（画师模式）；新人物在正文/占位符报一次外貌；同名人物带身份标签
- **提示词像中文剧情文字？** 检查辅助模型是否遵守 `prompts/roster/system.txt`（禁止照抄场景）；格式硬约束会整轮作废不合格输出
- **刷新后历史图片不显示？** v1.1 已修复：加载后 12s 就绪探测 + DOM 观察器，按 `消息ID#块序号` 精确恢复
- **缓存总是一次聊天就丢？** v1.1 已修复：不再每次页面加载清空；仅首次升级时清理一次旧缓存
- **没图？** 大多数情况是主模型没在正文里写 `[img:…]` 占位符 → 检查角色卡/预设/世界书是否贴了 `prompts/main-llm-instruction.txt`（面板「复制小猫指令」）
